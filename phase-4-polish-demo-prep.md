### 4.5 — Edge Case Handling

Test and handle:
- [ ] Empty chief complaint → triage still works (vitals-only)
- [ ] All vitals normal + vague complaint → should give ESI-4 or 5
- [ ] All vitals critical → should give ESI-1 with high confidence
- [ ] Gemini API timeout → fallback explanation displays
- [ ] Duplicate patient names → handled by UUID
- [ ] Rapid re-triage clicks → debounced, no race conditions

### 4.6 — Performance Check

- [ ] Triage computation completes in <5 seconds (including LLM)
- [ ] Queue page loads in <2 seconds with 50 patients
- [ ] No visible lag during demo

### 4.7 — Q&A Prep (3-Minute Q&A Session)

Likely judge questions and prepared answers:

| Question | Answer |
|---|---|
| "How is this different from ChatGPT doing triage?" | "The LLM doesn't decide — it explains. The actual classification is done by our trained ML model + deterministic red-flag rules. The LLM is layer 3 of 3." |
| "Would this work with real data?" | "The architecture would — swap the synthetic dataset with de-identified clinical data, retrain the model, and add proper auth/HIPAA compliance. The pipeline is the same." |
| "How do you handle model errors?" | "Every output has a confidence score. The clinician always makes the final call and can override. Every decision is audit-logged." |
| "What model did you train?" | "A Random Forest classifier on tabular vital signs + symptom indicators. We chose it over deep learning because tabular clinical data is where tree-based models excel." |
| "Why not just use deep learning?" | "For structured vital-sign data, gradient boosted trees consistently outperform neural nets. Deep learning would be appropriate for imaging or long clinical notes — not our use case." |
